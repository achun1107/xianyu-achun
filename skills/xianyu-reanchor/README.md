# xianyu-reanchor（重锚）

> 把一条已有浏览量的闲鱼死链接，重新锚定到新场次上。
> `itemId` 不动、分类不动、价格不动、规格不动 —— 只换它"说什么"，不换它"是谁"。

## 名称来由

「重锚」的两个字都来自 GEO（Generative Engine Optimization）的第一性原则：**实体一致性**。

检索系统判断一个东西时不看措辞，看实体。同一个实体被多套措辞描述，就认不成同一个，只能各自降权。
所以 GEO 的第一根杠杆不是"多发内容"，而是"把已有实体的表述统一"——**存量资产优先于新建资产**。

闲鱼链接是同一回事，只是层级更低：链接被平台收录、有搜索词沉淀、有人群标签、有评价和 DSR。
**改老链接 = 实体（itemId）不变、语义（标题/正文/主图）更新**，权重跟着走。
新发链接 = 新实体 = 从零建立信任。

这就是「重锚」：不换实体，只换锚点。

## 快速开始

```powershell
# 1. 按浏览量挑一条（别按感觉挑）
node tools/item-traffic.js --top=10

# 2. 出主图（必须带现役版式）
$env:KUN_EVENT="演唱会"; $env:KUN_MAIN_TPL="__shoukai"
node publish-one.js 广州 王嘉尔 首开 --dry

# 3. 改链接（不加 --go 只预览）
node tools/apply-item.js <itemId> \
  --main="<主图>" --title="<30字内标题>" --descFile="<正文文件>" \
  --addrCity=广州 --go

# 4. 验收（唯一权威判据是在售清单）
node tools/list-onsale.js --ids=<itemId>
```

## 为什么值得做

| | 新发链接 | 重锚老链接 |
|---|---|---|
| 权重 | 从零冷启动 | 继承历史曝光 / 人群标签 / 评价 |
| 曝光 | 等平台试推 | 立刻进原有的曝光位 |
| 风险 | 审核未过就白等 | 类目/价格/属性不动，稽查面小 |
| 代价 | — | 丢掉老标题沉淀的那部分搜索词（靠 7 天过渡期缓解） |

## ⛔ 先过这道闸：这条链接能不能动

**只有「已过场 + 零成交 + 非在投」三条同时满足，才是可重锚的链接。**

2026-11-12 我按浏览量把 `1067404891764`（9435 浏览，排第一）当成老链接改了，
它其实是 **33561 曝光 / 26 笔成交 / ¥21523.95 成交额** 的主力链接。
老板原话：「你改造老链接，不能拿我正在上架的链接改啊」——原正文 2480 字无备份，只能借同款 270 字恢复。

**浏览高 ≠ 可改，浏览高恰恰说明它是活的。**

## 什么时候别用

- 有成交（`xianyu-商品索引.csv` 的「支付额」> 0）
- 高曝光（浏览 > 5000）
- 正在投推广（`node tools/ad-status.js` 能看到）
- 新场次和原场次**类目不同** → 换上就是换宝贝，高危
- 原链接**已下架**（`status=1`）→ PC 改完还是下架，重上架只能用 App
- 商品还在**审核中**（`status=-9`）→ 先等过审

## 五个坑（详见 SKILL.md）

1. 无规格商品不能按有规格发（`闲鱼太累啦～` 不一定是限流）
2. 改完不要马上开推广（广告侧要等 30–60 分钟同步）
3. 只改区划会留下旧 POI 名（广州番禺区 + 「长沙站」）
4. 标题 30 字硬上限，平台从尾部静默砍；模板1≡2、模板3≡4
5. 改的是文案和图，**别碰类目/价格/品牌/属性**
