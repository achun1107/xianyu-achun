# 切点节奏结构提炼：三种节奏结构三选一，从切点分布反推原始剪辑做法

## R — 原文 (Reading)

> 「这是复刻时最该保留的东西——不是画面内容，是"什么时候切、切多密"与口播语义的关系。hypit 的 `reference-video.md` 说的正是这件事："Cue boundaries are author intent"。」（L284）
> 「### 三种节奏结构 = 三种"可复刻的行为"」（L276）
>
> — source.md《一、三条参考片的客观结构》L276–284；切分口径见「镜头切分（ffmpeg scene 阈值 0.22）」L228

---

## I — 方法论骨架 (Interpretation)

把参考片的切点（镜头边界）量化成表，再从表的形状反推剪辑者当时怎么下刀。
切点由 ffmpeg scene 检测得到、阈值固定 0.22；有了切点时间戳，就算相邻间隔、段时长、平均镜长。
三条参考片呈现出三种稳定结构：①全程约 2s 快切，节奏由句读驱动；②两个长镜 + 只在一处做 0.5s 等距的卡点蒙太奇；③前段十几秒一镜到底（长口播/整页录屏），到演示段才开始切。
归类之后反推原始做法——何时切、切多密由什么驱动，这是复刻时真正要保留的东西：保留结构与口播语义的关系，不是原片的秒数。
推断要分级：相邻双切点像转场（闪白/叠化）、0.5s 等距像卡点，没逐帧验证前只能标"候选"。

## A1 — 应用示例 (Application Example)

### 示例 1: 三条参考片归类（原书实测案例）
- **类型与来源**: 原书案例；source.md L228–284；verified.md V-03 数据核对
- **问题/输入**: AI小凯 12 段（25.783s）、Lindsay 7 段（36.033s）、Scrapling 10 段（36.433s）的切点表
- **方法的使用**: 按间隔形状三选一归类 → AI小凯 = ①全程快切（25.783 ÷ 12 = 2.1486 ≈ 2.15 s/镜 ✓）；Lindsay = ②长镜 + 单点卡点（段 6 内 27.03/27.53/28.03/28.53/29.03/29.53 相邻步长恒 0.5s ✓；4.033/4.067 相邻双切点 → 转场候选）；Scrapling = ③前长后短（16.50 − 0.13 = 16.37s 一镜到底 ✓）
- **结论/预期输出**: 三行节奏表 + 推断的原始做法（句读驱动 / 讲解段不切、只在一处密集蒙太奇 / 演示段才切）
- **结果**: 原书 L276–284 成表给出三种结构与推断做法

### 示例 2: 新片切点表归类演练（合成演练，纸面）
- **类型与来源**: 合成演练（verified V2"新输入演练"，按原书规则可复算）；原书未提供该新片，非作者经历
- **问题/输入**: 切点表 [0, 2.1, 4.0, 6.3, 8.2, …]；[0, 4.0, 11.0, 13.0, 26.0（内含 0.5s 等距段）, 30.0]；[0, 0.13, 16.5, 18.6, 20.8, …]
- **方法的使用**: 算间隔 → 三选一归类
- **结论**: 第 1 组间隔 ≈2s 均匀 → 归类①；第 2 组含 0.5s 等距段 + 长镜 → 归类②；第 3 组前段 16.37s 无切、其后 2s 级快切 → 归类③
- **结果**: 三组均可由切点表复算，expected = observed（纸面核对通过）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 切点表已到手（或需要先跑 scene 检测），要归纳参考片的节奏结构
2. 写分镜 / SVML / Script 时要"保留切点节奏"，需要一个可执行的结构口径
3. 想知道参考片"什么时候切、为什么切"，把剪辑做法反推出来
4. 多条参考片横比节奏风格，或给新片套用某条参考的结构
5. 用户抱怨"节奏不对/太碎/太拖"，需要量化判断而不是凭感觉改

### 语言信号 (用户的话里出现这些就应激活)

- "切点分析" / "cut points / scene detection / shot pacing"
- "节奏结构 / 几秒一刀 / 切太密 / 节奏太慢"
- "卡点蒙太奇 / 一镜到底 / beat sync"
- "这个片子的剪辑节奏怎么复刻" / "replicate the cut rhythm"
- "Cue boundaries / 节奏表 / 节奏归类"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `reference-breakdown-two-round`（V-01）：V-01 负责把片拆开并分级证据（切点数据也由它产出），本卡只吃切点表做归类与反推，不产出全片报告
- 与 `layout-pixel-spec`（V-02）：时间维度 vs 空间维度，互不替代——V-02 管"摆哪多大什么色"，本卡管"何时切切多密"
- 与 `sound-recipe-replicate`（V-04）：本卡管画面切点，V-04 管 BGM/音效卡点；两者对齐属下游合成，不在本卡

## E — 可执行步骤 (Execution)

**输入契约**: ①切点时间戳序列（秒，含片头 0 与片尾）②检测阈值固定 0.22（原书口径 L228；选取理由原书未给，标为约定，换片复跑不得更改）③缺切点表 → 先跑 ffmpeg scene 检测；"刀/分钟"分母原书未给口径 → 不使用该指标，用段表 + 平均镜长替代。

**输出契约**: 节奏表，列：段号 / 起止（s）/ 时长（s）/ 归类（①②③）/ 推断的原始做法 / 证据等级（候选 | 已核）；附量化口径：段数、平均镜长 = 总时长 ÷ 段数（保留 2 位小数，约定）。转场类推断未逐帧验证一律标"候选"。

1. **沿用阈值 0.22 生成切点表**
   - 完成标准: 时间戳序列完整，表结构与原书三表一致；换片复跑时阈值未被改动
2. **计算间隔并三选一归类**
   - 完成标准: 每段有起止与时长；归类可由间隔复算——均匀 ≈2s → ①，存在 0.5s 等距密集段 + 长镜 → ②，前段十几秒无切、演示段起切 → ③；核对示例 25.783 ÷ 12 ≈ 2.15
   - 判停条件: 若表既不符合①的均匀、也不含②的等距卡点、也不是③的前长后短 → 停止外推，记"三类不覆盖"回阶段 1.5 待核查，不硬套（"适用于一切知识口播类参考片"是已剔除的外推 p02）
3. **反推原始做法并标证据等级**
   - 完成标准: 每行归类都有推断做法；相邻双切点（4.033/4.067 型）→ 转场候选、0.5s 等距 → 卡点蒙太奇候选，未逐帧验证不写成结论
4. **输出节奏表**
   - 完成标准: 表含段号/起止/时长/归类/推断做法 + 段数与平均镜长，可直接交给分镜/SVML 环节

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单镜头且全程无切的片 —— 三类不覆盖，别硬塞进③（③要求后段开始切）；此时如实记"不覆盖"
- 声音卡点分析（BGM/音效何时响）—— 归 V-04
- 版式坐标规格 —— 归 V-02
- "照搬原片秒数"式复刻 —— 本卡的产出是结构，V3 明确要把"按原秒数放"替换为"按新片语义段落套结构"

### 作者在书中警告的失败模式

- 换片复跑擅改阈值 0.22 → 跨片比较失效（L228；选取理由原书未给，属约定）
- 把转场/卡点"候选"推断写成结论 —— 未逐帧验证不具备结论资格
- 外推"适用于一切知识口播类参考片"—— 样本仅 3 条知识片，p02 已剔除
- BOOK_OVERVIEW 骨架 2 的结构①"单镜头一镜到底"与 source L278 冲突，以 source 为准（缺口 G-3）

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 三条样本、单一平台（抖音）、单一垂类，迁移性未验证
- 假设"结构 = 可复用资产"足以带来同类表现，未做 A/B 验证
- 以工程可复现为先，对"内容本身好不好"（文案钩子强弱）着墨少——节奏对了不等于流量
- 依赖 hypit/ffmpeg 当日版本行为，工具升级可能失效

### 容易混淆的邻近方法论

- "按原片秒数排时间轴"（换文案后仍按原秒数摆放，ce08 型错误）—— 那是 V-06 渲染环节的锚定问题，本卡给的是可套用的结构而非秒数
- 每分钟刀数（"刀/分钟"）这类单一密度指标 —— 分母口径缺失，本卡以段表 + 平均镜长 + 归类为口径
