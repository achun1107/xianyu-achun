## I — 方法论骨架 (Interpretation)

验收不靠"看起来差不多"，而是把成片帧和参考帧**并排**放在一张图里，对着前面量出来的规格表逐项打勾：标题的 x/y、字幕的 y 区间、色值（#FFD700 + 黑描边）、字高百分比、画幅与分辨率口径（9:16、720×1280）。规格表来自像素级实测（V-02），没有实测表就没有可比的项——方位词（"左上角""底部"）不是验收依据。
每一项的判定语言是二值加偏差量："通过"或"偏差 X"，打回必须写出触发项，验收结论不允许出现"差不多""还行"这类没有数值的表述。
顺序上有讲究：**画幅/分辨率先查**。工具选错画幅（比如拿只做 16:9 的工具出抖音竖屏片）时流水线每一步都能跑通、最后导出才发现错，这是失败暴露最晚、返工成本最高的一项，所以放最前面当闸门。
对比之外还要跑一遍确定性自检找回归（`--det` 思路：开关的具体检查项书内未展开，保留思路级）。产出物是两张硬东西：并排对比图 + 逐项偏差清单；任一项超出容差就打回，不放行。
还要预留一个"坐标全绿仍不像"的出口：字体这类没被坐标捕获的自由度，要单列检查，不能让逐项对齐的绿灯替它背书。

## A1 — 应用示例 (Application Example)

### 示例 1: 画幅冲突——最晚暴露的返工
- **类型与来源**: 原书转述的工具约束/失败边界（反例 ce13）；source.md L353
- **问题/输入**: 要出一条抖音 9:16 竖屏片，顺手选了 vibe-knowledge-film（其能力边界是只做 16:9 横屏）
- **方法的使用**: 按本卡规则把"画幅核对"当第一道闸——选工具时就对目标平台画幅规格，而非导出后才发现
- **结论**: 工具输出画幅与平台内容规格不匹配时，流水线全程绿灯也会产出不能用的成片
- **结果**: 原书以分工表中的约束条目给出（成片不能用），未记录实际打回事件

### 示例 2: 逐项并排验收（合成演练）
- **类型与来源**: 原书未提供完整验收实操，以下为按 source L376 + L390–393 实测表规则的合成演练
- **问题/输入**: 参考片规格（720×1280：顶部标题 x≈90（12.5%）、y≈205–340（16–27%）、#FFD700 + 黑描边、字号≈58；底部字幕居中 y≈940–1050（73–82%）；画幅 9:16）+ 一条新出的成片 mp4
- **方法的使用**: 同时间点抽帧并排 → 先核画幅 9:16 与分辨率口径 → 再逐项对 x/y、色值、字高%（换算按百分比口径，容差 ±1px）→ 记偏差清单
- **结论**: 每项输出"通过 / 偏差 X"；任一项超约定容差 → 打回
- **结果**: 合成演练——预期输出为对比图 + 偏差清单；原书未报告实际验收结果

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 成片刚渲染完，交付前要确认和参考片到底像不像、哪里偏了
2. 改了字体/样式/坐标重渲之后，要查有没有改坏（回归检查）
3. 多轮迭代后说不清"这次比上次好还是坏"，需要固定口径的对比
4. 流水线跑通了但有人质疑"感觉不对"，要把感觉翻译成逐项偏差
5. 选工具/模板阶段就要把画幅、分辨率这类最贵的错误先拦住

### 语言信号 (用户的话里出现这些就应激活)

- "验收 / 对比参考片 / 逐项对坐标 / 哪里不像 / 像不像"
- "验收清单 / 打回标准 / acceptance / side-by-side compare / diff review"
- "看起来差不多但说不上哪不对 / quality gate / regression check"
- "画幅对不对 / 竖屏还是横屏 / aspect ratio"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `storyboard-local-pipeline`（V-06）的区分: V-06 负责把片渲染出来（含样片过审门），本卡是全片出完后的独立验收动作；样片门≠终验
- 与 `layout-pixel-spec`（V-02）的区分: V-02 测参考片产出规格表（量一次），本卡拿规格表去比成片（查每版）；没规格表先去 V-02
- 与 `reference-breakdown-two-round`（V-01）的区分: V-01 拆的是参考片一侧的事实，本卡比的是成片与参考的差
- 与 `douyin-clean-asset-extract`（V-05）的区分: V-05 管输入素材干净与否，本卡管输出成片与参考的对齐度

## E — 可执行步骤 (Execution)

**必需输入**: ①成片 mp4 ②参考片 mp4 ③V-02 实测规格表，必含字段：元素 x/y（或百分比）、色值、字高%、画幅/分辨率——缺任一字段 → 先回 V-02 补测，不以方位词代替坐标。容差约定（原书未给数值阈值，以下为本卡约定，沿用 V-02 换算口径）：坐标换算 ±1px；百分比按约值口径（±0.5% 量级）；色值须一致；画幅/分辨率须一致（0 容差）。
**输出契约**: ①并排对比图（同时间点抽帧成对）②逐项偏差清单（元素 / 参考值 / 成片实测值 / 偏差 / 结论）③打回或放行的明确结论。对齐项以 source 实测表为准：坐标 / 色值 / 字高 / 画幅；"亮度"无实测字段对应（缺口 G-9），取得测量口径前不列入验收项。

1. **画幅与分辨率核对（前置闸门）**
   - 完成标准: 成片画幅（9:16）与分辨率口径（720×1280 或等比换算值）与参考一致
   - 判停条件: 画幅不符 → 直接打回，不进入逐项对比（ce13：画幅失败暴露最晚、返工最贵）

2. **抽帧拼图（sheet 思路）**
   - 完成标准: 每个验收元素（标题、字幕、花字、标注）在成片与参考各取一帧，组成并排图；确定性自检（--det 思路）跑一遍找回归

3. **并排逐项对比**
   - 完成标准: 每个元素逐项对 x/y、色值（如 #FFD700 + 黑描边）、字高%，全部给出"通过 / 偏差 X"；偏差按上述约定容差判定

4. **字体单列复查**
   - 完成标准: 检查压制字体是否已换为原片字体；坐标色值全对但"说不上来的不像" → 判为字体项不通过（ce14）
   - 判停条件: 字体未换 → 打回 V-06 步骤 4，不因坐标全绿放行

5. **输出偏差清单与结论**
   - 完成标准: 对比图 + 逐项偏差清单齐全；任一项超容差或画幅不符 → 打回并写明触发项；全项通过 → 放行

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 手里没有 V-02 实测规格表 —— 没有可比基准，先去测量；本卡不产生规格，只消费规格
- 主观审美讨论（"这个文案好不好""选题行不行"） —— 本卡只判与参考的对齐度，不判内容优劣
- 30 秒样片的过审门 —— 那是 V-06 的步骤 5，本卡是全片级逐项验收

### 作者在书中警告的失败模式

- **ce13 画幅不匹配** —— 只做 16:9 的工具出抖音竖屏片，全程跑通最后才发现，返工最贵（L353）
- **ce14 坐标全绿仍不像** —— 不换原片字体，逐项对齐拦不住字形偏差（L119、L141）
- **ce08 卡点错位进验收** —— 换文案后按原秒数摆放导致包装层与口播错位，验收时表现为时间项全偏（L118）
- **凭"看起来差不多"放行** —— 无逐项结论的验收等于没验收（原书以逐项实测表 + 对比审片为口径）

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 验收"亮度"项无实测字段对应（G-9），`--sheet/--det/--motion` 具体检查项未展开（P-5）——本卡对齐清单以 source 实测表为界，其余记待补
- "结构 = 可复用资产"未做 A/B 验证：验收全绿只证明"像参考"，不证明"有流量"
- 最强反对意见（原书批判）：版式复刻的边际收益可能远小于文案与选题的边际收益——别把本卡的绿灯当成内容成功的证据

### 容易混淆的邻近方法论

- V-06 的样片门是**过程质检**（过/不过二值，防系统性错误铺量），本卡是**终验**（逐项偏差，防改坏/没像）；两者都过不代表内容成立
- 主观的"感觉不对"不是本卡输入；把它翻译成逐项对比才是
