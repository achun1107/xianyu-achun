# 声音配方复刻：BGM 来源判定与参数检索、音效按事件卡点摆放

> 「在抖音/小红书原视频页面看音乐标签：显示歌名 → 现成曲目；显示「@作者创作的原声」→ 作者自己上传」（L50）

## I — 方法论骨架 (Interpretation)

声音配方 = BGM 四件套（BPM、调性、情绪、段落变化点）+ 音效事件表（时间点 / 类型 / 对应画面 / 依据等级）。两件事分开做。
第一件是来源判定：参考片的 BGM 是曲库现成曲、作者自传还是 AI 生成？证据不足时只有先验（60/20/20），先验不是结论。
确认路径固定为 if-then：查原视频页面音乐标签（歌名 → 现成曲目；@作者创作的原声 → 作者自传），不够再听歌识曲 / ACRCloud，识别不到就标"来源待确认"并停止断言。
第二件是复刻：按 BPM/情绪/调性检索曲库或 AI 生成免版权曲。
音效按表摆放，依据分两档——deterministic_anchored 的直接用，"信号候选（低置信）"的先人工听审；卡点优先落在文字/贴纸出现的帧上；程序合成音效时音高要对齐 BGM 调性。
随身带着一个坑：BPM 有倍频歧义（145.6 可能是 72.8 或 291.2），没核验前不按单一值定案。

### 示例 1: fentiao_ref 声音配方（原书实测案例）
- **类型与来源**: 原书实例；source.md L46–67、L117；verified.md V-04
- **问题/输入**: BPM 145.6（歧义 72.8/291.2）、F major（0.725）、段落变化点 5.0s；音效 6 处（1 处 `deterministic_anchored` @3.54s + 5 处信号候选）；卡点统计（花字 2、标题 1、文字标注 1）
- **方法的使用**: 走来源 if-then 判定 → BGM 按参数检索/生成 → 音效按依据档摆放 → 卡点对齐文字事件
- **结论/预期输出**: 来源判定路径明确；6 处音效中 4 处卡在文字/贴纸出现帧（L117）
- **结果**: 原书落地复刻动作 L52/L67；修正不采纳：候选 p07"每处 whoosh/pop 都对齐包装元素"与 L117（4/6）不符，以 4/6 为准；p20"占 63%"算术冲突（11s ÷ 13.5s ≈ 81%）不使用该字段（P-4）

### 示例 2: 声音配方复刻 walkthrough（纸面演练）
- **类型与来源**: 演练（verified V2 walkthrough，按原书规则可复算）
- **问题/输入**: BGM 四件套（BPM 145.6 含歧义、调性 0.725）+ 音效表 6 处（含依据等级）
- **方法的使用**: ①来源 if-then：页面音乐标签显示歌名 → 现成曲目；显示「@作者创作的原声」→ 作者自传；仍不确定 → 听歌识曲/ACRCloud；识别不到 → 标"来源待确认"（判停，不把先验当结论）②按 BPM/情绪/调性检索或 AI 生成 ③3.54s 直接用；0.02/0.85/1.04/6.25/7.07 先人工听审 ④卡点优先文字/贴纸出现帧 ⑤程序合成音高对齐调性

- **结果**: 纸面闭环；BPM 歧义保留括注，裁定方法原书未给（缺口 G-6）→ 摆卡点前不按单一 BPM 定案

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拆解报告里已有 BGM 四件套与音效表，要为新片实际找/做配乐与音效
2. 需要判断参考片 BGM 来源，以决定走曲库检索还是 AI 生成这两条完全不同的产出线
3. 摆音效卡点时要区分"可直接用"与"必须听审"的证据等级
4. 卡点对不上、BPM 对不上，怀疑倍频/半频歧义
5. 用户问"这条片子的音乐怎么复刻、音效怎么摆"

### 语言信号 (用户的话里出现这些就应激活)

- "BGM 怎么找 / 复刻配乐" / "replicate the BGM / find similar music"
- "音效卡点 / whoosh 放哪" / "SFX placement / sound recipe"
- "BPM 对不上 / 是 145 还是 72" / "tempo ambiguity / half-time doubt"
- "这首是曲库歌还是 AI 生成" / "stock music or AI-generated"
- "按 BPM/调性检索" / "match the key and tempo / 音高对齐调性"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `reference-breakdown-two-round`（V-01）：V-01 产出声音统计与来源不确定点（取证），本卡执行检索/生成/摆放（复刻）；"来源待确认"从 V-01 流转进来
- 与 `rhythm-structure-extract`（V-03）：V-03 归类画面切点节奏（何时切镜头），本卡管声音节奏与音效事件（何时响起）；对齐两者属下游合成
- 与 `storyboard-local-pipeline`（V-06，阶段 3 再建卡）：本卡出配方与摆放清单，把音轨真正合进成片是 V-06 的渲染环节

## E — 可执行步骤 (Execution)

**输入契约**: ①BPM（数值 + 歧义括注）②调性 + 置信度 ③段落变化点（可选）④音效表（时间点 / 类型 / 对应画面 / 依据等级）⑤来源判定状态（现成曲目 | 作者原声 | 待确认）。缺 BPM 或音效表 → 询问，不静默猜值。

**输出契约**: 两条轨（BGM、音效）+ 配方单：每处音效含时间点、处置（直接用 | 听审后用 | 弃用）、依据等级；来源字段为三值枚举（现成曲目 | 作者原声 | 待确认），无第四种"当确认"；卡点对齐文字/贴纸事件帧；程序合成音高对齐调性（原书约定 L67）；BPM 歧义在未核验前一律括注保留。

1. **来源 if-then 判定**
   - 完成标准: 查过原视频页面音乐标签（歌名 → 现成曲目；@作者创作的原声 → 作者自传）；仍不确定 → 听歌识曲 / ACRCloud 识别
   - 判停条件: 识别不到 → 来源写"待确认"并停止断言（不把 60% 先验当结论），直接进步骤 2 做参数检索，跳过"按来源选产出线"
2. **获取 BGM**
   - 完成标准: 按 BPM/情绪/调性检索曲库或 AI 生成免版权曲；BPM 歧义（145.6/72.8/291.2）保留括注——未用听感或段落变化点（5.0s）核验前，不按单一 BPM 定案摆卡点
3. **摆放音效**
   - 完成标准: 依据等级为 `deterministic_anchored` 的点（3.54s）直接用；5 处信号候选（0.02/0.85/1.04/6.25/7.07）全部经人工听审后才保留；每处保留/弃用有记录
4. **卡点对齐与交付**
   - 完成标准: 卡点优先落在文字/贴纸出现帧（原书 4/6 处口径）；程序合成时音高对齐 BGM 调性；输出 BGM 轨 + 音效轨 + 每处依据等级标注

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 参考片无 BGM / 无音效 —— 无配方可复刻
- 音轨分离、混音母带等工程细节 —— 原书只到"检索与摆放"，不覆盖混音
- 把音轨真正压制进成片 —— 归 V-06 渲染环节，本卡只交付配方与摆放清单
- 纯找歌、听歌的娱乐需求 —— 本卡是复刻工程，不是音乐推荐

### 作者在书中警告的失败模式

- **ce09**：凭画面先验断定 BGM 来源——AI 生成配乐与曲库配乐在音频上根本分不开，60/20/20 的先验会被当事实传播；误判直接换掉产出线（曲库检索 vs AI 生成）
- **ce15**：BPM 倍频歧义不核验就按 145.6 摆卡点——自相关在整数倍周期同样出峰，卡点整体错位一倍或半倍
- 修正不采纳：p07"每处 whoosh/pop 都对齐某个包装元素"与 L10/L117 不符（实际 4/6）；p20"占 63%"存在算术冲突，本单元不使用该字段

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 只讲"怎么像"，不讲版权边界：BGM 与参考素材的使用责任留给使用者（立场盲点）
- 单一平台（抖音）、单一垂类样本；依赖工具链当日版本
- 假设"结构 = 可复用资产"未做 A/B 验证；对"内容本身好不好"着墨少——声音复刻得再准也补不了钩子弱

### 容易混淆的邻近方法论

- "把每处音效都对齐包装元素"的均匀化理解 —— 原书口径是 4/6，不是全部
- "来源待确认就随便挑一条曲子" —— 与本卡不同：检索照做（按参数），断言不做（来源字段停在"待确认"）
- 画面切点节奏归类（V-03）—— 对象是镜头边界，不是声音事件
