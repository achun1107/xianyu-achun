## I — 方法论骨架 (Interpretation)

这条流水线回答的问题是：规格书都有了，怎么在自己机器上把同结构的新片**可复跑**地生产出来。骨架是五段：环境就绪 → 词级转写 → 包装层渲染 → 30 秒样片 → 铺全片。
环境就绪不是"装完就算"：pnpm 10 默认拦截依赖的构建脚本，esbuild/koffi 的原生二进制不会生成，要加白名单；ffmpeg 要单独装且装完得开新 shell 才进 PATH；终点是 `hypit doctor` 0 diagnostics 加一次 media 命令冒烟。
词级转写产出 `transcript.json`，它是写 Script 的锚——后面所有花字、标注的时间都要挂在"某句台词开始后 N 秒"上，而不是抄参考片的绝对秒数；选型按本机显存降档，不硬上大模型。
包装层渲染有两个确定的坑：hypit 的描边是"Stroke 双倍宽度 + Fill 后写盖内半边"，图层顺序就是算法本身，写反整字变色；ASS 压制前必须把字体换成原片字体，否则坐标色值全对也"说不上来的不像"。
节奏控制的核心是小样先行：先做 30 秒样片，过审（过/不过二值）再铺全片——系统性错误（锚点写法、节奏保留、样式配方）一处错处处错，小样把返工成本锁定在常数上。

## A1 — 应用示例 (Application Example)

### 示例 1: 描边图层顺序的失败/成功对照
- **类型与来源**: 原书亲历（案例 c09，反例 ce01）；source.md L396
- **问题/输入**: hypit 组件文字样式需要黄字黑描边；按图形学通用直觉先写 Fill 再写 Stroke
- **方法的使用**: 按渲染器私有约定重排——Stroke 写在 Fill 前面（描边双倍宽度，后写的 Fill 盖住内半边形成单侧描边）
- **结论**: 图层顺序是描边算法的一部分，属于隐式契约，必须记进配方
- **结果**: 失败表现"整字变描边色"、按正确顺序写即恢复，由原书对照给出；未提供更细的成功截图数据

### 示例 2: 五步清单的执行状态
- **类型与来源**: 原书执行清单（L370–376）+ 亲历实测（案例 c07）；转写步状态见 source L313【进行中】
- **问题/输入**: 本机从零搭 hypit 出片环境
- **方法的使用**: ①`pnpm install` → 补 `onlyBuiltDependencies: [esbuild, koffi]` → winget 装 Gyan.FFmpeg 9.0.2（新 shell 生效）→ `hypit doctor` → media 冒烟 ②`hypit transcribe --to transcript.json --language zh` ③写第一份 30 秒 SVML ④接 museav ⑤`hypit build` 出片 + 拼图审片
- **结论**: 环境步的失败点（pnpm 拦截、ffmpeg PATH）都有确定修法
- **结果**: 环境步成功——doctor 0 diagnostics、42 个子命令、media probe/tile/frames/boundaries 实测可用；转写步原书标【进行中】，是否跑通未说明（缺口 G-4）

### 示例 3: 花字按台词锚定的演算
- **类型与来源**: 原书例题（案例 c14，worked_example）；source.md L118、L136–139
- **问题/输入**: 首句字幕 0.00–3.90s，花字「合澜」1.00s 出现、「Vailifteaa」2.50s 出现；后续要换文案
- **方法的使用**: 把绝对秒数换算为句锚偏移——「合澜」= 该句开始后 1.0s、「Vailifteaa」= 该句开始后 2.5s；换文案后按新句起点重算
- **结论**: 锚点是"某句开始后 N 秒"，不是时间轴绝对坐标
- **结果**: 演算表即原书给出的结果；换文案后的实际重排效果原书未说明

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 参考片规格已备齐，要在本机搭环境出第一版片（hypit 装完不确定能不能跑）
2. 有了词级转写，要写第一份分镜 Script / SVML，且只先做 30 秒小样
3. 换了文案，花字、字幕、音效卡点要跟着句子重排
4. 渲染出来的文字颜色不对（整字变描边色）或成片字体"说不上来的不像"
5. 铺量前要确认样片过没过审、卡点节奏有没有丢

### 语言信号 (用户的话里出现这些就应激活)

- "出片 / 跑流水线 / 本地渲染 / 搭 hypit 环境 / 写第一份分镜脚本"
- "30 秒样片 / 先出个小样 / sample first / render pipeline"
- "换文案后花字位置怎么改 / 台词锚定 / dialogue anchor"
- "stroke fill 顺序 / 描边变色 / 字体不像 / storyboard-driven production"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `douyin-clean-asset-extract`（V-05）的区分: V-05 负责拿到干净素材，本卡从"素材已在手"开始，不下载任何东西
- 与 `remake-acceptance-diff`（V-07）的区分: 本卡负责把片渲染出来（含 30 秒样片的过审门），V-07 是全片出完后的逐项并排验收
- 与 `measure-to-shoot-plan`（V-08）的区分: V-08 是实拍/重拍分支（怎么拍），本卡是合成与包装分支（怎么渲染出片）
- 与 `reference-breakdown-two-round`（V-01）的区分: V-01 逆向参考片产出规格，本卡消费规格产出新片

## E — 可执行步骤 (Execution)

**必需输入**: ①干净素材（V-05 产出或用户提供）②参考规格（V-02 坐标配色表 + V-03 节奏归类，缺 → 先回前置能力补，不用方位词/估数代替）③本地环境（pnpm、ffmpeg、Chrome）④转写端点可用。缺失处理：缺本地环境 → 先搭环境不开工；缺转写端点 → 本步挂起，不写 Script。
**输出契约**: `transcript.json`（词级时间戳）→ 30 秒样片 mp4 → 全片 mp4；发布文案缺省按 `subtitles.srt` 文本导出并标注来源（原书未展开，缺口 G-8）；每个花字/标注必须带"某句开始后 N 秒"锚。样片门按"过审/未过审"二值执行（三问逐字原文缺，P-5，不补造内容）。

1. **环境就绪**
   - 完成标准: `pnpm install` 后白名单已加（`onlyBuiltDependencies: [esbuild, koffi]`）、ffmpeg 在**新 shell** 中 `-version` 可识别、`hypit doctor` 0 diagnostics、media probe 冒烟通过
   - 判停条件: CLI 报缺 koffi.node/esbuild → 回查白名单（ce05）；`ffmpeg -version` 不识别 → 开新 shell 重试（ce06）；两项不通过不进步骤 2

2. **词级转写**
   - 完成标准: `hypit transcribe <原片> --to transcript.json --language zh` 产出含词级时间戳的 transcript.json
   - 判停条件: 显存 ≤6GB → 用 medium / cpu / int8，不硬上 large-v3（ce07）；转写端点未跑通 → 挂起并记录（原书该步即【进行中】，G-4），不进入步骤 3

3. **写 30 秒样片 Script/SVML**
   - 完成标准: Script 用转写里的词、保留参考片切点节奏归类（V-03）；每个花字/标注写成"某句开始后 N 秒"锚而非绝对秒数（ce08）
   - 判停条件: SVML 语法细节书内未给（P-8）→ 策略层执行到"先 30 秒 + 用转写词 + 保留节奏"，语法问题查 hypit 自有文档

4. **渲染与压制**
   - 完成标准: 样式中 Stroke 写在 Fill 前面（渲染结果为字内填充色、仅边缘描边色，ce01）；压制用 `ffmpeg -vf ass=overlays.ass` 且字体已换成原片字体（ce14）
   - 判停条件: 整字变描边色 → 顺序写反，回改本步；字体未换 → 不进入步骤 5

5. **样片过审**
   - 完成标准: `hypit build` 出 30 秒样片并完成审片，结论为"过审"（拼图审片 + 确定性自检思路；开关具体检查项书内未展开，P-5）
   - 判停条件: 未过审 → 不铺量（ce18），回改后重渲样片

6. **铺全片 → 导出**
   - 完成标准: 全片 mp4 导出；换文案后卡点复查——每个包装元素仍落在对应句子起点后 N 秒；发布文案按 srt 文本导出并标注

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 没有干净素材或参考规格就开工 —— 本卡不获取素材、不做逆向测量（回 V-05 / V-01 / V-02）
- "今天就要出一条片"且无本地环境 —— 原书分工表指向 MUSE AV 中台模板（填字段就出片，L350），本卡是可复跑可编辑的重生产线
- 只想拆解参考片、不产出新片 —— 那是 V-01/V-03 的任务

### 作者在书中警告的失败模式

- **ce01 描边顺序写反** —— 整字变描边色，成片直接报废（L396）
- **ce05 pnpm 10 拦截构建脚本** —— install 全绿但原生模块缺失，报错不指向白名单（L295）
- **ce06 缺 ffmpeg / PATH 未生效** —— 全链路失败，旧 shell 重试误判"装不上"（L296、L381）
- **ce07 小显存硬上 large-v3** —— OOM 中断，"更大模型=更好"的直觉只换来转写失败（L329）
- **ce08 换文案仍按原秒数摆放** —— 包装层与口播错位，卡点全偏（L118）
- **ce14 不换原片字体直接压制** —— 坐标色值全对仍"说不上来的不像"（L119、L141）
- **ce18 不做样片直接铺全片** —— 系统性错误按片长放大，返工成本绑定全片渲染时长（L374）

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 依赖工具链当日版本行为：hypit/ffmpeg/whisperx 升级可能让描边顺序、doctor 口径等经验失效
- SVML 语法、"三问"逐字内容、编译期校验均不在书内（P-5、P-8、G-7、G-10），本卡只能执行到策略层
- 以工程可复现为先，对"内容本身好不好"（文案钩子强弱）着墨少——流水线跑通 ≠ 片子有流量
- "结构 = 可复用资产"未做 A/B 验证（未被证明的假设）

### 容易混淆的邻近方法论

- vibe 的三问/审片是**质检思路**，不是本流水线的渲染步骤；三问原文未取得前只按"过审/未过审"二值使用
- 中台模板出片（MUSE AV）是"填字段即出"的快路径，与本卡"可编辑可重跑"的编排层不是同一条线
