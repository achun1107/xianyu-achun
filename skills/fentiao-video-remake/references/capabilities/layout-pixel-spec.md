## I — 方法论骨架 (Interpretation)

第一轮拆解给的是统计与文字描述，给不到坐标级规格；要复刻版式，就得单独做一轮像素级实测。
做法是：选定基准分辨率坐标系（原片 720×1280），逐个元素量出位置（x、y 或 y 区间）、色值（如 #FFD700）、字高（px），并把每个量同时写成"px + 百分比"两个口径。
百分比是关键：x% = x ÷ 基准宽 ×100，字高% = 字高 px ÷ 基准高 ×100，规格因此能等比迁移到任意分辨率（如 1080×1920），不用重新量。
测量口径必须随表写明：数值由主体像素测得，没有人脸时用画面清晰区域并标"估算"；平台转码会压暗部，读数偏保守。
测量与看图结论冲突时两者并列，不擅自取舍。
字段不全（缺 bbox/色值/字高任一）就停，不用"左上角""靠下"这类方位词冒充坐标。

## A1 — 应用示例 (Application Example)

### 示例 1: c05 作者亲历——工具给不到坐标级，另做一轮实测
- **类型与来源**: 原书亲历案例（候选 c05）；source.md L387–393 版式实测记录；verified.md V-02
- **问题/输入**: 参考片 fentiao_ref.mp4（720×1280），第一轮拆解只给了"标题/字幕/黄字黑描边"的文字描述，无坐标
- **方法的使用**: 抽帧 → 逐元素测 x/y/色值/字高 → 双写 px 与 % → 形成实测表
- **结论**: 顶部标题 x≈90（12.5%）、y≈205–340（16–27%）、#FFD700 + 黑描边、字号≈58；底部字幕居中 y≈940–1050（73–82%）
- **结果**: 实测表落地于 L390–393；描边厚度未测（原表只记"黑描边"无厚度，缺口 G-2）

### 示例 2: 坐标换算核验与新分辨率迁移（V2 walkthrough，纸面演练）
- **类型与来源**: 演练（按原书规则可复算）；verified.md V-02 换算核验
- **问题/输入**: 基准 720×1280 实测表；目标片 1080×1920
- **方法的使用**: 核验 12.5%×720=90 ✓；16%×1280=204.8≈205 ✓；73%×1280=934.4≈940 ✓；字高抽核 51→51÷1280=3.98%≈4.0% ✓（表内 12 行均满足 字高% = px ÷ 1280 ×100）。迁移：标题 x=135px、y=307–518px；字幕 y=1402–1574px；字号 58→87px；主色 #FFD700 不变
- **结论**: 等比换算可复用，容差 ±1px
- **结果**: expected = observed（核对通过）；候选 p06 称"8 组字高"实为 10 组不同值，计数偏差不影响公式

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 第一轮拆解完成，要把版式变成可复刻的规格表（坐标/色值/字高）
2. 新片分辨率与参考片不同（720×1280 → 1080×1920），要把规格等比换算过去
3. 验收成片时需要逐项对齐的基准值（给 V-07 并排对比供数）
4. 用户抱怨"版式总是差一点/看起来不像"，需要量化而不是凭感觉调
5. 用户直接要"量一下"：字幕在百分之几的位置、标题多大、主色是什么

### 语言信号 (用户的话里出现这些就应激活)

- "帮我量一下这条参考片的版式" / "measure the layout"
- "字幕坐标 / 字高 / 色值 / 字号换算"
- "layout spec / pixel measurement / bbox / font size in %"
- "换到 1080×1920 还准吗" / "scale the spec to another resolution"
- "position, color, text height spec / 像素级规格"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `reference-breakdown-two-round`（V-01）：V-01 是第一轮取证与证据分级，本卡是第二轮实测；V-01 的报告是本卡的入口，本卡的实测表回供 V-07 验收
- 与 `rhythm-structure-extract`（V-03）：V-03 管时间轴（何时切、切多密），本卡管空间版式（摆哪、多大、什么色），互不替代
- 与 `sound-recipe-replicate`（V-04）：本卡只管画面文字元素；BGM/音效规格归 V-04

## E — 可执行步骤 (Execution)

**输入契约**: ①可抽帧的参考片或截图 ②基准分辨率（宽×高，px，必须显式给出）③待测元素清单（标题/字幕/花字/文字标注…）。缺基准分辨率或元素边界 → 询问，禁止用方位词代替坐标。

**输出契约**: 实测表，列：元素 / x（px+%）/ y 或 y 区间（px+%）/ 色值 / 字高（px+%）/ 字号。公式：x% = x ÷ 基准宽 ×100；字高% = 字高 px ÷ 基准高 ×100；百分比四舍五入到 0.1%（约定）；迁移：目标 px = % × 目标边长，容差 ±1px（约定，来自 walkthrough）。% 与 px 必须双写；估算值标"估算"。

1. **逐项像素实测**
   - 完成标准: 每个元素都有 x、y（或 y 区间）、色值、字高 px 四类字段
   - 判停条件: 任一元素缺 bbox/色值/字高 → 停止，不以方位词或"差不多"补值
2. **百分比换算并抽核**
   - 完成标准: 每行满足 字高% = px ÷ 基准高 ×100（如 51→4.0%、99→7.7%、63→4.9%、29→2.3%），% 与 px 双写；抽核全部行通过
3. **迁移目标分辨率**
   - 完成标准: 目标 px 按公式算出并标容差 ±1px；主色等非尺寸量保持不变
4. **标注口径与不确定项**
   - 完成标准: 每个"估算"值有标注；测量与看图冲突处两者并列记录（L109 口径）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只有文字描述、没有可抽帧画面 —— 无像素可测
- 纯定性问"版式什么风格" —— 本卡产出数值规格，不产出风格描述
- 成片逐项比对验收 —— V-07 拿本卡的表当基准做对比结论，本卡不产出对比结论
- 原书未测的字段（如描边厚度，缺口 G-2）—— 缺就标缺，不补造数值

### 作者在书中警告的失败模式

- 本单元 verified 未挂靠反例 id；对应失败模式是判停明文——"无实测表即停止，不以方位词代替坐标"（缺字段即停，不猜值），以及 L109 的"测量与看图冲突必须并列"
- 候选反例 ce03「肉眼估版式偏 10%+」因无 source.md 原句（缺口 G-1）已淘汰，不作为本卡依据；其指向的"凭感觉估版式"仍是本卡要替代的做法

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 单一平台、单一垂类样本；依赖工具链当日版本
- 只讲"怎么像"不讲版权边界；假设"结构 = 可复用资产"未做 A/B 验证
- 最强反对意见：版式复刻的边际收益可能远小于文案与选题——版式量得再准也补不了钩子弱

### 容易混淆的邻近方法论

- 肉眼估计、"看起来差不多"式调整 —— 不可量化、不可验收，不是本卡
- 工具自动生成的统计描述（"黄字黑描边"）—— 那是 V-01 第一轮的产出，没有坐标，不满足本卡输入契约
