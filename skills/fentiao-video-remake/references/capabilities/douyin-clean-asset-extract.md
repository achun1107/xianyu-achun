# 抖音无水印素材提取与烧录字预处理

## R — 原文 (Reading)

> 抖音无水印原片提取走 web aweme/detail 接口（页面内 X-Bogus 签名），play_addr 为无水印流；素材几乎都带烧录字，组装前要挑无字片段或换素材。
>
> — source.md · 附录「复刻落地三条经验」第 3 条（L398）

> 三条都是有口播的竖屏/横屏知识片。全部无水印、无角标（douyin/抖音原视频提取方法.md 已验证）。
>
> — source.md · 第二部分「三条参考片的客观结构」（L226）

## I — 方法论骨架 (Interpretation)

抖音分享页和客户端都不能直接"另存"出干净原片：存下来的是带平台水印/角标的东西，不能当复刻底料。
确定路径只有一条：在抖音 web 详情页的**页面上下文**里，用页面自己加载的签名器（`frontierSign` → X-Bogus）给 `aweme/detail` 接口签名，从返回的 `bit_rate[]` 列表里取最高码率档的 `play_addr`——这条流才是无水印原始转码档（`download_addr` 是带水印那条）。下载必须带 Referer，直链约 1 小时过期。
拿到文件只完成了一半：参考素材几乎都带**烧进像素**的旧字（旧标题、旧字幕），它没有图层、关不掉，跟"画面里物体上的字"、"可导出的外挂字幕"是三回事，必须分开登记。
所以流程后半段是抽帧检查：有烧录字就挑无字片段，挑不出就换素材——问题在组装前暴露，而不是在成片验收时穿帮。
产出物 = 干净 mp4 + 三项检查记录（无水印 / 无角标 / 无可疑烧录字）。

## A1 — 应用示例 (Application Example)

### 示例 1: 三条参考片的无水印提取
- **类型与来源**: 原书亲历（案例 c10）；source.md L226、L398；配套文档 `douyin/抖音原视频提取方法.md`（frontierSign → X-Bogus → play_addr 步骤与「本次结果」表）
- **问题/输入**: 三个抖音分享链接（Lindsay / AI小凯 / Scrapling），分享页与客户端都无法直接保存无水印原片
- **方法的使用**: 短链重定向取视频 ID → 打开 `douyin.com/video/<ID>` 在页面内 `frontierSign({url})` 签名 → 请求 `aweme/v1/web/aweme/detail/` → 按码率降序取 `play_addr.url_list[0]` → 带 Referer 下载 → 抽帧验证
- **结论**: `play_addr` 即无水印流，页面内签名是该路径的必要条件（脱离页面签名就是空响应）
- **结果**: 成功——3 个文件（1920×1080 / 2160×3840，25.78–36.43s），抽帧确认画面无抖音水印、无抖音号角标

### 示例 2: 烧录字前置检查（合成演练）
- **类型与来源**: 原书未提供该片段的具体处理结果，以下为按 source L398 规则的合成演练
- **问题/输入**: 一条已通过无水印检查的 mp4，抽帧发现底部有一行与本次文案无关的旧字幕
- **方法的使用**: 按三类登记——烧进像素的后期文字（L398）/ 画面里物体上的字如「40」「e」（L184）/ 可导出的外挂字幕（L119）→ 判为烧录字 → 在时间轴上挑无字片段
- **结论**: 挑不出无字片段即换素材，不带烧录字进流水线
- **结果**: 合成演练——预期输出为"可用片段区间 + 三类登记表"；原书未说明实际挑段结果

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 手里只有抖音分享链接，要拿原片做逆向/复刻，但分享页下载的都带水印
2. 参考素材已下载却带抖音角标/水印，需要换一份干净底料
3. 抽帧发现素材画面里带烧录字，判断还能不能用、怎么处理
4. 要按"同作者同模板"思路批量提取同一作者多条视频
5. 下载报 403 / 直链打不开 / 拿到的不是视频文件，需要正确的请求方式

### 语言信号 (用户的话里出现这些就应激活)

- "无水印下载 / 去水印 / 抖音原片 / 提取原视频"
- "这条视频怎么保存 / download this douyin video without watermark / no watermark / clean footage"
- "素材上带字幕怎么办 / 烠录字能不能去掉 / burned-in text"
- "直链 403 / 下载下来打不开 / 拿到的是错误页"

- 与 `storyboard-local-pipeline`（V-06）的区分: 本卡管"素材从哪来"（拿到干净底料），V-06 管"素材怎么变成片"（转写/渲染/压制/铺量），V-06 不做任何下载

## E — 可执行步骤 (Execution)

**必需输入**: 抖音分享链接或视频 ID（缺失 → 先询问，不猜 ID）；可打开 douyin.com 的浏览器环境（签名依赖页面上下文，缺 → 先解决环境再执行）。
**输出契约**: 干净 mp4 + 检查记录表，字段为「文件名 / 分辨率 / 时长 / 水印 / 角标 / 烧录字三类登记与处置结论」，三项检查全为"通过"才算完成。方法细节见配套文档 `douyin/抖音原视频提取方法.md`。

1. **短链 → 视频 ID**
   - 完成标准: 从分享短链重定向的 location 头拿到 `iesdouyin/share/video/<ID>/` 中的 aweme_id

2. **页面内签名取无水印直链**
   - 完成标准: 在 `douyin.com/video/<ID>` 页面上下文调用 `window.byted_acrawler.frontierSign({url})` 得到 X-Bogus，请求 `aweme/v1/web/aweme/detail/` 返回 `aweme_detail.video.bit_rate[]`，按码率降序取最高档的 `play_addr.url_list[0]`
   - 判停条件: 签名空响应 / 接口失效 → 停止并记录，不降级用带水印流；若改用配套文档的 `currentSrc` 降级方案，必须先抽帧确认无水印，确认不了同样停止

3. **带 Referer 下载并验文件**
   - 完成标准: 请求头带 `Referer: https://www.douyin.com/`，文件头为 `ftyp`，时长与平台显示一致
   - 判停条件: 403 → 补 Referer 重试；直链约 1 小时过期 → 回步骤 2 重签；文件头非 `ftyp` → 视为错误页，重取

4. **抽帧检查烧录字（三类登记）**
   - 完成标准: 每段素材对三类文字各标"有/无"：烧进像素的后期文字（关不掉）/ 画面里物体上的字（如「40」「e」）/ 可导出的外挂字幕
   - 判停条件: 有烧录字 → 进步骤 5；无 → 直接进步骤 6

5. **挑无字片段或换素材**
   - 完成标准: 组装用片段内无可疑烧录字；挑不出无字片段 → 换素材，不带字进流水线（问题不后移到验收）

6. **输出干净 mp4 + 检查记录**
   - 完成标准: 三项检查（无水印 / 无角标 / 无可疑烧录字）全部有记录且通过

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 手里已有原始拍摄素材或已验证的干净原片 —— 无需提取，直接进 V-06 / V-08
- 非抖音平台的视频 —— 本路径是抖音 web 接口专用（frontierSign、`bit_rate[].play_addr` 均为抖音口径）
- 只想快速看一眼内容 —— 带水印预览足够，不必走签名提取流程

### 作者在书中警告的失败模式

- **ce02 素材带烧录字直接进组装** —— 旧字幕与新包装层同框穿帮，烧录字没有图层关不掉，只能选段或换素材（L398）
- **签名脱离页面上下文** —— X-Bogus 必须在页面里签，脱离浏览器签名就是空响应（配套文档明文警告）
- **ce10 把转码后缺失的元数据当"没有"** —— 下载件元数据被平台清除是链路副作用，不代表原片没有该信息（L206）

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 只讲"怎么像"，不讲版权边界：参考素材与他人成片的使用责任完全留给使用者
- 依赖抖音接口的当日可用性（task-04 尚缺条件），接口签名算法升级可能让本卡步骤整体失效
- 单一平台样本，其他平台的提取路径未验证

### 容易混淆的邻近方法论

- "去水印工具 / 第三方解析站"：那是对带水印流做后处理的兜底思路，产物是处理过的画面；本卡取的是平台原始无水印转码档，两者底料质量不同
