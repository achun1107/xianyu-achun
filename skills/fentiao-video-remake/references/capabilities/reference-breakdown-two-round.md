# 参考片两轮逆向取证与证据分级

## R — 原文 (Reading)

> 「判断置信度（按时长加权）60%；判定方式：仅确定性取证；未开 VLM；实拍/AI/3D 的区分只靠像素统计，可信度有限。」（L13）
> 「确定性取证对「是否在动、是否整图推拉、是否渲染纹理、是否 24→30 帧率转换」很可靠；对实拍 / AI / 3D 的区分要依赖 VLM 与人工复核。」（L205）
>
> — source.md《视频拆解报告：fentiao_ref.mp4》L13、L205；另见「不确定点」L167–171

## I — 方法论骨架 (Interpretation)

拆一条参考片要走两轮，两轮回答的问题不同。
第一轮用拆解工具（rea-video）拿结构与证据：结论行、时长与镜头数、按时长加权的置信度、底层画面 mix 表、包装层清单（字幕/花字/标题/标注）、声音统计、逐镜取证，全量数据落在 breakdown.json。
第二轮是像素级实测——工具给不到坐标级，得自己量出元素的 x/y、色值、字高。
登记画面时按三层模型拆：底层画面、包装层、烧录字，不混在一列。
核心纪律是"每个结论都带来源和置信度"：确定性取证（动/推拉/纹理/帧率）可以当结论用；实拍 vs AI vs 3D、BGM 来源这类弱信号只能当候选。
低置信项不丢弃，进"不确定点"清单，每条必须附一个具体可执行的复核动作（配 VLM 重跑，或让看图 agent 逐镜复核）。
最后一条：元数据缺失是平台转码的副作用，不是"没有"的证据。

## A1 — 应用示例 (Application Example)

### 示例 1: fentiao_ref.mp4 拆解输出三处不确定点
- **类型与来源**: 原书实例（拆解报告实际输出）+ V2 walkthrough（纸面演练，非宿主实测）；source.md L13、L15、L169–171；verified.md V-01
- **问题/输入**: 一条 13.5s、720×1280 的参考片 mp4，rea-video 环境可用但未配置 VLM
- **方法的使用**: ①跑拆解得报告与 breakdown.json ②读置信度：整体 60%、逐镜实拍 59%（次选 ai_video 29%）→ 全部标"低置信" ③按三层模型登记（实拍 100% 底层 + 字幕/标题/花字包装层 + 画面里物体上的字"40、e"）④低置信项写进不确定点并附复核动作 ⑤元数据缺失不作反证
- **结论/预期输出**: 报告含镜头/包装/声音统计 + 不确定点清单（每条带确定的复核动作）
- **结果**: 原书报告输出 3 处不确定点（VLM 未生效、镜头 #1 实拍仅 60% 置信、BGM 来源待确认），每条附 `--vlm` 重跑或看图复核动作（L169–171）；复核是否实际完成：未说明。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 拿到一条想复刻的参考视频，需要先系统拆它：镜头、包装、声音、素材各是什么，哪些能直接用
2. 拆解报告里出现"置信度 60%""待确认""可信度有限"，需要判断哪些结论能信、哪些必须复核
3. 需要把参考片转成可交付的结构产物（报告 + breakdown.json + 不确定点清单）交给下游环节（版式实测、节奏提炼、分镜）
4. 要判断画面类型（实拍/AI/3D）或素材来源，且知道工具只给了弱信号
5. 别人（或工具）给了一份拆解数据，要验收它的证据等级是否齐全

### 语言信号 (用户的话里出现这些就应激活)

- "拆解这条参考片" / "break down this reference video"
- "逆向这条视频" / "reverse engineer this clip"
- "拆解报告 / 置信度 / 低置信 / 不确定点 / 待确认"
- "reference breakdown / confidence level / uncertain points"
- "这个视频是怎么做出来的，帮我拆一下"

### 与相邻能力的区分（初稿，阶段 3 定稿）

- 与 `layout-pixel-spec`（V-02）：本卡是入口轮，产出结构与证据分级；坐标级规格来自第二轮实测，归 V-02。本卡回答"是什么、多可信"，V-02 回答"摆在哪、多大、什么色"
- 与 `rhythm-structure-extract`（V-03）：V-03 只从切点表做节奏归类与反推；本卡覆盖全片取证（切点数据也由它产出），不做归类
- 与 `sound-recipe-replicate`（V-04）：本卡只登记声音统计与来源不确定点；检索 BGM、摆音效是 V-04 的事

## E — 可执行步骤 (Execution)

**输入契约**: ①参考片文件（mp4 等，路径明确）②rea-video 可用环境（VLM 可选）③无 VLM 时须有"能看图的 agent 或人工"作复核替代。缺参考片路径或工具不可用 → 先询问/停机，不降级换别的片子代替。

**输出契约**: 拆解报告（结论行 + 时长/镜头/置信度 + mix 表 + 包装层清单 + 声音统计 + 逐镜取证）+ breakdown.json 出口 + 不确定点清单（每条含：项、当前置信、确定的复核动作）。低置信项必须显式标注，不得以确定性语气输出；元数据缺失一律记"缺失 ≠ 没有"。

1. **跑第一轮工具拆解**
   - 完成标准: 报告与 breakdown.json 均生成，结论行/镜头/包装/声音统计字段齐全（对照 L10–L69、L207）
2. **读置信度与判定方式，给每个结论标来源与置信度**
   - 完成标准: 每个结论旁有"确定性取证/信号候选"或置信百分比
   - 判停条件: 若已配置 VLM 或有看图 agent → 升级复核（`REA_VLM_BASE_URL/API_KEY/MODEL` + `--vlm` 重跑，或 `rea-video review` + `apply-review` 并入）后回本步重标；若两者都不可用 → 跳到步骤 4，全部低置信项标注"未复核"，不把 60% 当 100% 用
3. **按三层模型登记画面**
   - 完成标准: 底层画面 / 包装层 / 烧录字三列各有条目；画面里物体上的字（如"40、e"）归入烧录字类，不与后期字幕混列
4. **汇总不确定点并附复核动作**
   - 完成标准: 每条低置信项都进清单且带一个具体动作（`--vlm` 重跑 / review / 看图复核），没有"待确认"裸条目
5. **元数据与缺失字段收尾检查**
   - 完成标准: 报告中无"没有记录 = 不存在"式结论；缺失字段显式标注原因（平台转码清除等）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只想知道"这条视频讲什么"的纯内容查询 —— 本卡产出结构与证据，不是内容概括（原书本身也注明整片概括需 VLM）
- 没有可拆的视频文件、只有一句话描述 —— 无输入可取证
- 成片 vs 参考的逐项比对验收 —— 那是 remake-acceptance-diff（V-07）的活，本卡的报告是它的输入之一

### 作者在书中警告的失败模式

- **ce04**：未开 VLM、只靠确定性取证就采信画面类型结论——报告会以确定性语气输出 60% 置信结果，使用者容易当 100% 用；「内容与结构」「角色」章节直接空缺，后续建立在残缺取证上
- **ce10**：把平台转码后缺失的元数据当成"没有"，得出错误溯源结论（L206 明文"缺失不代表没有"）

### 作者的盲点 / 时代局限（BOOK_OVERVIEW「3. 批判」）

- 单一平台（抖音）、单一垂类（钢材/五金）样本，结论迁移性未验证
- 依赖 rea-video/hypit/ffmpeg 当日版本行为，工具升级可能失效
- 只讲"怎么像"不讲版权边界；以工程可复现为先，对"内容本身好不好"着墨少
- 假设"结构 = 可复用资产"足以带来同类表现，未做 A/B 验证

### 容易混淆的邻近方法论

- 凭肉眼估版式、"看起来差不多"式取证 —— 不是本卡；且"肉眼估偏 10%+"缺原书原句（缺口 G-1），不作为依据
- 单纯跑一遍工具、不做证据分级 —— 那只是步骤 1，缺了步骤 2–5 不构成本能力
